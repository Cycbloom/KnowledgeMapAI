## 实施计划

### 任务 1：更新前后端导入路径使用共享类型
**优先级：中**

**步骤：**
1. 检查前端代码中哪些文件使用了本地类型定义
2. 检查后端代码中哪些文件使用了本地类型定义
3. 更新这些文件从 `@shared/types` 导入类型
4. 验证类型检查通过

### 任务 2：组件目录重组
**优先级：中**

**步骤：**
1. 创建目录结构：
   - `src/components/common/` - 通用组件
   - `src/components/features/` - 功能组件
   - `src/components/layout/` - 布局组件
2. 识别通用组件（如 Button、Modal、Loading 等）
3. 迁移 Scheduler 相关组件到 `features/Scheduler/`
4. 迁移 GraphEditor 相关组件到 `features/GraphEditor/`
5. 迁移 Study 相关组件到 `features/Study/`
6. 更新所有导入路径
7. 运行类型检查验证

### 任务 3：错误处理统一
**优先级：低**

**步骤：**
1. 创建 `shared/types/errors.ts` 统一错误类型
2. 检查现有错误处理中间件
3. 创建前端错误处理工具函数
4. 统一 API 响应格式

### 任务 4：文档和测试更新
**优先级：低**

**步骤：**
1. 检查测试文件是否需要更新导入路径
2. 更新项目文档说明新的目录结构

---

## 风险和注意事项

1. **组件迁移风险**：组件迁移涉及大量导入路径更新，需要仔细检查
2. **测试验证**：每次重构后运行 `npm run check` 确保类型正确
3. **渐进式迁移**：可以按功能域逐步迁移组件

## 预期收益

- 类型定义统一，减少重复代码
- 组件按功能域组织，易于查找和维护
- 错误处理一致，提升用户体验
- 文档完善，便于团队协作
