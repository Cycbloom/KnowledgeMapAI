# Implement 3D Performance Tiering & LOD Optimization

This plan aims to introduce a performance management system to optimize 3D graph rendering for different device capabilities.

## 1. State Management (`src/store/usePerformanceStore.ts`)
Create a new Zustand store to manage performance settings:
- **State**:
    - `quality`: 'high' | 'medium' | 'low' (persisted in localStorage)
    - `showStats`: boolean
    - `fps`: number (transient)
- **Logic**:
    - `high`: Bloom enabled, 32-segment spheres, full draw distance.
    - `medium`: Bloom disabled (or reduced), 16-segment spheres, 80% draw distance.
    - `low`: No effects, 8-segment spheres, 50% draw distance, simplified materials.

## 2. Performance Monitor (`src/components/Graph3D/PerformanceMonitor.tsx`)
Create a component to:
- Monitor FPS using `useFrame`.
- Update the store with current FPS.
- **Auto-downgrade Suggestion**: If FPS < 30 for 5 consecutive seconds, trigger a toast suggestion to lower quality.

## 3. Rendering Optimization
### `src/components/Graph3D/GraphRenderables.tsx`
- **Geometry LOD**: Dynamically switch `sphereGeometry` args based on quality tier (32x32 vs 16x16 vs 8x8).
- **Text LOD**: Apply a multiplier to `visibleDistance` based on quality (1.0x / 0.8x / 0.5x).

### `src/components/Graph3D/GraphScene.tsx`
- **Post-Processing**: Conditionally render `<EffectComposer>` and `<Bloom>` only on 'high' quality.
- **Background**: Reduce or disable `<Stars>` count on 'low' quality.

## 4. UI Integration (`src/components/GraphEditor/GraphSettingsModal.tsx`)
- Add a **Performance** section.
- Add "Quality" selector (High/Medium/Low).
- Add "Show FPS" toggle.

## 5. Verification
- **Test Case**: Verify manual quality switching changes visual fidelity (geometry segments, bloom).
- **Test Case**: Verify FPS monitor updates.
- **Test Case**: Verify settings persist across reloads.
