# Phase 1: Refine Mobile UX and Gestures

The current implementation of `GraphEditor` completely swaps the 3D view for a 2D `GraphOutline` on mobile devices. This makes the mobile-specific layout logic inside `GraphToolbar` redundant (dead code) and creates an inconsistent codebase.

To optimize the mobile UX and clean up the technical debt, I will:

1.  **Refactor `GraphToolbar.tsx`**:
    *   Remove the internal `isMobile` state and the unused mobile render block (Dead Code Elimination).
    *   The toolbar will now focus solely on the Desktop 3D view controls.

2.  **Enhance `GraphEditor.tsx` (Mobile View)**:
    *   The mobile view (Lines 1102+) currently lacks some functionality present in the toolbar (e.g., Settings, Export, Undo/Redo).
    *   I will add a **Mobile Action Sheet / Menu** to the `GraphEditor`'s mobile header to expose missing features:
        *   **Settings**: Access to graph settings.
        *   **Export**: Basic export options.
        *   **Theme Toggle**: Dark/Light mode switch.

3.  **Optimize `GraphOutline` for Mobile**:
    *   Ensure the list view is touch-friendly (larger tap targets).
    *   (Already implemented but will verify) Verify batch actions are accessible.

4.  **Standardize `useIsMobile`**:
    *   Ensure `GraphEditor` uses the standard hook (already doing so).
    *   Remove ad-hoc `window.innerWidth` checks in other components if found.

## Implementation Steps

1.  **Modify `src/components/GraphEditor/GraphToolbar.tsx`**:
    *   Remove `useState(window.innerWidth < 768)` and `useEffect` for resize.
    *   Remove the `if (isMobile) { ... }` render block.
    *   Simplify props interface (remove unused props if any were only for mobile).

2.  **Modify `src/pages/GraphEditor.tsx`**:
    *   Enhance the mobile header (Lines 1105-1117).
    *   Add a "More" button (`MoreVertical` icon) to trigger a mobile dropdown/sheet.
    *   Implement the dropdown to show: "Theme", "Settings", "Export", "Help".

3.  **Verification**:
    *   Since I cannot physically test touch gestures, I will verify that the code structure logically supports the new mobile UI elements.
    *   Verify desktop view remains unaffected.

This approach acknowledges that **Mobile = 2D Outline** is the current design choice (likely for performance), and optimizes the UX within that constraint rather than forcing a heavy 3D view on mobile.
