# Phase 2 Part 2: Rich Media Export

The current PDF export is a simple GET request that dumps text. It lacks visual context (the graph itself) and customization.

I will implement a "Rich Export" feature that includes:
1.  **Frontend**: A new `ExportDialog` that captures the current 3D graph view as an image.
2.  **Backend**: A refactored PDF generator that accepts this image and produces a professional report.

## 1. Frontend: Export Dialog & Screenshot Capture
- **New Component**: `src/components/GraphEditor/ExportDialog.tsx`
- **Features**:
    - Preview area showing the report layout.
    - **Screenshot**: Use `gl.domElement.toDataURL()` from the Three.js canvas to capture the current view.
    - **Options**: Toggle "Include Screenshot", "Include Node Details", "Include Stats".
    - **Action**: POST to `/api/data/export/pdf` with the screenshot (base64) and options.

## 2. Backend: Enhanced PDF Generation
- **Refactor**: Move the inline PDF logic from `api/routes/data.ts` to a new service `api/services/pdfService.ts` to keep the route clean.
- **New Capabilities**:
    - **Image Support**: Embed the base64 screenshot on the cover page.
    - **Better Typography**: Improve headers, spacing, and layout.
    - **Table of Contents**: Add hyperlinks if possible (pdfkit supports basic links).
- **Route Update**: Change `/export/pdf` to support `POST` method (to accept the large base64 image body).

## 3. Implementation Steps
1.  **Create `api/services/pdfService.ts`**: Move and upgrade PDF logic.
2.  **Update `api/routes/data.ts`**: Add POST handler for PDF export.
3.  **Create `ExportDialog`**: Implement UI and canvas capture logic.
4.  **Integrate**: Update `GraphToolbar` to open the dialog instead of direct download.

This will transform the export from a simple text dump into a shareable, visual knowledge report.
