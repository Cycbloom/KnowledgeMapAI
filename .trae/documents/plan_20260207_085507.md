# 初始化预设模板到数据库

## 问题分析
- 目前预设模板（概念学习、问题解决、编程学习、历史学习、科学实验、四象限分析）只是硬编码在 `api/services/templateService.ts` 中
- 数据库中没有 `templates` 表
- 前端调用 `/api/templates` 时，只能获取到用户自定义模板（如果有的话），获取不到预设模板

## 解决方案

### 1. 创建数据库迁移文件
创建 `supabase/migrations/20260208000000_add_templates_table.sql`，包含：
- `templates` 表结构：
  - `id` (UUID, PRIMARY KEY)
  - `user_id` (UUID, nullable, 用于用户自定义模板)
  - `name` (VARCHAR(255))
  - `description` (TEXT)
  - `category` (VARCHAR(20): 'learning' | 'story' | 'project' | 'analysis' | 'custom')
  - `is_system` (BOOLEAN, DEFAULT false)
  - `nodes` (JSONB)
  - `edges` (JSONB)
  - `layout` (JSONB)
  - `created_at`, `updated_at`
- 索引：`user_id`, `category`, `is_system`
- RLS 策略：
  - 匿名用户可以查看所有模板（包括系统预设）
  - 认证用户可以查看所有模板
  - 认证用户可以创建自定义模板
  - 只有模板创建者可以更新/删除自己的模板
  - 系统预设模板不能被修改/删除

### 2. 初始化预设模板数据
在 migration 中插入 6 个预设模板：
- 概念学习模板
- 问题解决模板
- 编程学习模板
- 历史学习模板
- 科学实验模板
- 四象限分析模板（带布局配置）

### 3. 修改后端代码
修改 `api/services/templateService.ts`：
- 移除硬编码的 `presetTemplates` 数组
- 改为从数据库查询系统预设模板（`is_system = true`）
- 保持现有的 `listTemplates`, `getTemplate`, `createTemplate`, `updateTemplate`, `deleteTemplate` 方法不变

## 实施步骤
1. 创建 migration 文件
2. 执行 migration（或让用户执行）
3. 修改 templateService.ts 移除硬编码
4. 测试验证预设模板可以正常获取
