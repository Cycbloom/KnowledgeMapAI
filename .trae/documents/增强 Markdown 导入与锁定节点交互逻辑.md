# 完善项目核心体验的建议方案

经过对项目代码的深入分析，您的项目核心功能（知识图谱渲染、FSRS 学习算法、闯关模式）已经非常完整。为了进一步提升“知识管理”和“游戏化学习”的体验，我建议优先完成以下两个高价值功能：

## 1. 增强 Markdown 导入功能 (支持 Obsidian 双链)
目前 `markdownParser.ts` 仅根据标题层级（H1, H2...）生成父子关系。但在实际知识库（如 Obsidian）中，`[[关键词]]` 形式的双向链接才是知识关联的核心。
- **目标**: 让导入器识别 `[[Node Title]]` 语法，自动创建跨层级的关联边。
- **价值**: 允许用户构建网状知识结构，而不仅仅是树状结构。

## 2. 完善“锁定节点”的交互逻辑
目前代码中 (`GraphRenderables.tsx`) 虽然将锁定节点渲染为灰色，但**没有阻止用户点击**。用户依然可以点击并进入详情页，这破坏了“闯关解锁”的游戏机制。
- **目标**: 在 3D 视图的点击事件中拦截对 `lockedNodeIds` 中节点的交互，并给出“请先掌握前置节点”的提示。
- **价值**: 闭环游戏化体验，确保用户必须按顺序学习。

# 实施计划

## 任务 1: 实现 Markdown 双链解析
1.  **修改 `src/utils/markdownParser.ts`**:
    -   新增正则匹配 `\[\[(.*?)\]\]`。
    -   在解析正文内容时，提取所有双链引用。
    -   在节点生成完毕后，遍历引用列表，查找目标节点的 ID，并生成 `relationship: 'relates_to'` 的新边。

## 任务 2: 实现锁定节点拦截
1.  **修改 `src/components/Graph3D/GraphRenderables.tsx`**:
    -   在 `InstancedNodes` 组件的 `handleInteraction` 或 `onClick` 处理函数中，增加对 `lockedNodeIds.has(node.id)` 的检查。
    -   如果节点被锁定，阻止调用 `onNodeClick`，并触发一个 Toast 提示（需确认项目中是否有 Toast 组件，若无则使用 `alert` 或简单提示）。

## 任务 3: (可选) 验证与测试
1.  创建一个包含 `[[链接]]` 的测试 Markdown 文本进行导入测试。
2.  在图谱中手动锁定一个节点，验证是否无法点击。
