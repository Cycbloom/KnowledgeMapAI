# 知识图谱高亮效果修复计划

## 问题分析

用户报告了两个主要问题：
1. **移动图谱时连线高亮效果不稳定**：移动图谱时，连线的高亮/暗淡状态应该保持，但目前出现问题
2. **点击顶点时高亮状态切换不灵敏**：点击节点时，高亮和暗淡状态的切换有时不生效

## 根本原因

通过代码分析，发现以下问题：

### 1. 状态更新不同步
在 `GraphEditor.tsx` 的 `handleNodeClick` 和 `handleCanvasClick` 中，三个相关状态是分开更新的：
- `focusedNodeId`（用于计算 `hasFocusMode`）
- `focusedNodeIds`（用于判断节点是否高亮）
- `focusedLinkIds`（用于判断连线是否高亮）

这导致在某些渲染周期中，`hasFocusMode` 可能已经改变，但 `focusedNodeIds`/`focusedLinkIds` 还未更新，造成视觉不一致。

### 2. 连线缺少透明度过渡效果
在 `MindMapNode.tsx` 中，节点有 `transition: opacity ${transitionDuration}ms ease` 实现平滑过渡。

但在 `MindMapLink.tsx` 中，连线的过渡效果只在 `linkAnimation === 'none'` 时生效：
```typescript
// 第 155 行
transition: 'stroke-width 0.2s, opacity 0.2s'
```
当使用其他动画效果时，过渡被覆盖为 `'none'`，导致状态切换时视觉突变。

### 3. 状态判断逻辑问题
`hasFocusMode` 的计算基于 `focusedNodeId !== null`，但这与 `focusedNodeIds` 的状态可能不同步。

## 修复方案

### 修改 1: `MindMapLink.tsx` - 添加透明度过渡效果

确保连线始终有平滑的透明度过渡，不受动画模式影响。

**文件**: `d:\KnowledgeMap\src\components\GraphEditor\MindMapLink.tsx`

修改 `animationStyle` 的逻辑，确保 opacity 过渡始终生效：
```typescript
const animationStyle = useMemo(() => {
  const baseTransition = 'stroke-width 0.2s, opacity 0.2s';
  
  switch (linkAnimation) {
    case 'flow':
      return {
        strokeDasharray: '10, 10',
        animation: 'dash 1s linear infinite',
        transition: baseTransition
      };
    case 'pulse':
      return {
        animation: 'pulse 2s ease-in-out infinite',
        transition: baseTransition
      };
    case 'dash':
      return {
        strokeDasharray: '5, 5',
        animation: 'dash 0.5s linear infinite',
        transition: baseTransition
      };
    case 'none':
    default:
      return {
        transition: baseTransition
      };
  }
}, [linkAnimation]);
```

### 修改 2: `GraphEditor.tsx` - 优化状态更新顺序

确保在点击节点和画布时，状态更新的顺序正确，避免中间状态。

**文件**: `d:\KnowledgeMap\src\pages\GraphEditor.tsx`

修改 `handleNodeClick` 函数，确保先设置 `focusedNodeId` 再设置其他状态：

```typescript
const handleNodeClick = useCallback((node: GraphNode) => {
  // 先计算所有需要的状态
  const focusedNodes = getFocusedNodes(node.id, nodes, edges);
  const focusedLinks = getFocusedLinks(focusedNodes, edges);
  const directChildren = getDirectChildren(node.id, nodes, edges);
  
  // 批量更新状态
  setSelectedNode(node);
  setSelectedNodeIds(new Set([node.id]));
  setSidebarMode('detail');
  setFocusedNodeId(node.id);
  setFocusedNodeIds(focusedNodes);
  setFocusedLinkIds(focusedLinks);
  state.setForceShowTextIds(new Set([node.id, ...directChildren]));
}, [setSelectedNode, setSelectedNodeIds, setSidebarMode, nodes, edges, setFocusedNodeId, setFocusedNodeIds, setFocusedLinkIds, state]);
```

修改 `handleCanvasClick` 函数，确保清空状态的顺序一致：

```typescript
const handleCanvasClick = useCallback(() => {
  // 批量清空状态
  setSelectedNode(null);
  setSelectedNodeIds(new Set());
  setFocusedNodeId(null);
  setFocusedNodeIds(new Set());
  setFocusedLinkIds(new Set());
  state.setForceShowTextIds(new Set());
  if (sidebarMode !== 'none' && sidebarMode !== 'outline') {
    setSidebarMode('none');
  }
}, [setFocusedNodeId, setFocusedNodeIds, setFocusedLinkIds, state, setSelectedNode, setSelectedNodeIds, sidebarMode, setSidebarMode]);
```

### 修改 3: `MindMapCanvas.tsx` - 优化 hasFocusMode 计算

确保 `hasFocusMode` 的计算更加健壮，同时考虑 `focusedNodeIds` 的状态。

**文件**: `d:\KnowledgeMap\src\components\GraphEditor\MindMapCanvas.tsx`

修改 `hasFocusMode` 的计算逻辑：
```typescript
const hasFocusMode = focusedNodeId !== null && focusedNodeIds.size > 0;
```

这样可以确保只有在真正有聚焦节点时才启用焦点模式。
