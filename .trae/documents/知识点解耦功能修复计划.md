# 知识点解耦功能修复计划

## 背景

根据对 `decouple-knowledge-points` 规格的检查，发现以下问题需要修复：

1. 后端 API 未完全切换到新的数据模型
2. AI 生成图谱时未集成知识点复用功能
3. 公共知识点审核 API 缺失
4. 联立视图渲染不完整

## 修复方案

### Task 1: 后端 nodes API 切换到新数据模型

**问题**: `api/routes/nodes.ts` 仍在使用旧的 `nodes` 表，需要切换到 `knowledge_points` + `graph_nodes` 架构。

**修改文件**: `api/routes/nodes.ts`

**修改内容**:

1. **创建节点 (`POST /nodes`)**:
   - 先创建 `knowledge_points` 记录
   - 再创建 `graph_nodes` 关联记录
   - 检查是否有相似知识点可复用（如果 `reuse_existing=true`）

2. **获取节点 (`GET /nodes/:id`)**:
   - 从 `graph_nodes` JOIN `knowledge_points` 查询
   - 返回组合后的 Node 类型

3. **更新节点 (`PUT /nodes/:id`)**:
   - 分离更新：知识点内容更新到 `knowledge_points`
   - 图谱特定属性（位置、层级）更新到 `graph_nodes`

4. **删除节点 (`DELETE /nodes/:id`)**:
   - 支持 `hard_delete` 参数
   - 软删除：更新 `graph_nodes.deleted_at`
   - 硬删除：调用 `hard_delete_knowledge_point` 函数

5. **批量操作**:
   - 适配新表结构的批量更新和删除

---

### Task 2: AI 生成图谱集成知识点复用

**问题**: `api/routes/autoGraph.ts` 的 `/save-nodes` 直接插入旧表，未检测相似知识点。

**修改文件**: `api/routes/autoGraph.ts`

**修改内容**:

1. **在 `/save-nodes` 接口中添加知识点复用逻辑**:
   ```
   对于每个要创建的节点：
   1. 生成标题+内容的 embedding
   2. 调用 search_similar_knowledge_points 检查相似度
   3. 如果相似度 >= 阈值（如 0.85），复用已有知识点
   4. 否则创建新的 knowledge_point
   5. 创建 graph_nodes 关联
   ```

2. **添加配置参数**:
   - `reuse_threshold`: 相似度阈值，默认 0.85
   - `auto_reuse`: 是否自动复用，默认 true

### Task 3: 添加公共知识点审核 API

**问题**: 前端定义了审核相关 API，但后端缺少实现。

**修改文件**: `api/routes/knowledgePoints.ts`

**新增 API**:

1. **`POST /knowledge-points/submit-public`**:
   - 将知识点 visibility 设为 'pending'
   - 执行自动审核（内容质量、重复检测）
   - 返回审核结果

2. **`GET /knowledge-points/public`**:
   - 查询所有 visibility='public' 的知识点
   - 支持搜索和分页

3. **`GET /admin/knowledge-points/pending`**:
   - 管理员获取待审核列表
   - 包含自动审核结果

4. **`POST /admin/knowledge-points/suggestions/:id/approve`**:
   - 批准知识点为公共
   - 更新 visibility 为 'public'

5. **`POST /admin/knowledge-points/suggestions/:id/reject`**:
   - 拒绝知识点
   - 记录拒绝原因

**需要新增的数据库表**（可选，用于记录审核历史）:
```sql
CREATE TABLE knowledge_point_suggestions (
  id UUID PRIMARY KEY,
  knowledge_point_id UUID REFERENCES knowledge_points(id),
  suggested_changes JSONB,
  submitted_by UUID REFERENCES users(id),
  auto_review_result JSONB,
  status VARCHAR(20) DEFAULT 'pending',
  reviewed_by UUID,
  reviewed_at TIMESTAMPTZ,
  rejection_reason TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```
