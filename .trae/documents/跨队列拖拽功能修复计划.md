# 任务调度器跨队列拖拽功能修复计划

## 问题分析

经过代码审查，发现以下问题：

### 1. SortableContext 嵌套冲突
- `Scheduler.tsx` 中有一个全局的 `SortableContext` 包含所有任务 ID
- 每个 `QueueColumn` 内部又有一个独立的 `SortableContext`
- 这种嵌套可能导致拖拽事件处理混乱

### 2. handleDragOver 中的状态问题
- `handleDragOver` 使用 `findTaskById` 查找任务，但该方法依赖 `displayQueues`
- 当 `localQueues` 被设置后，`displayQueues` 会改变
- 但在 `handleDragOver` 中设置 `localQueues` 后，后续的查找可能失败

### 3. 拖拽到空队列的处理
- 当拖拽到一个空队列时，`overId` 是 `queue-X`
- 代码需要正确识别这是队列的 droppable 区域

### 4. DragOverlay 显示问题
- `DragOverlay` 需要正确显示被拖拽的任务

## 解决方案

### 步骤 1: 重构 SortableContext 结构
- 移除 `Scheduler.tsx` 中的全局 `SortableContext`
- 保留每个 `QueueColumn` 内部的 `SortableContext`
- 这样每个队列独立管理自己的排序

### 步骤 2: 修复 handleDragOver 逻辑
- 在 `handleDragOver` 中正确处理跨队列拖拽的预览
- 使用 `active.data.current` 获取任务的初始队列信息
- 避免在拖拽过程中重复设置 `localQueues`

### 步骤 3: 修复 handleDragEnd 逻辑
- 正确识别目标队列（无论是拖到任务上还是拖到空队列）
- 正确计算目标位置
- 调用后端 API 更新任务队列

### 步骤 4: 改进 TaskCard 的 useSortable 配置
- 确保 `data` 属性包含完整的任务信息
- 这样在拖拽过程中可以直接获取任务数据

### 步骤 5: 添加调试日志（可选）
- 在关键位置添加 console.log 帮助调试

## 具体修改

### 文件 1: `src/pages/Scheduler.tsx`

1. 移除全局 `SortableContext`（第 354-358 行和渲染部分）
2. 修改 `handleDragOver` 逻辑，使用 `active.data.current` 获取初始队列
3. 修改 `handleDragEnd` 逻辑，正确处理跨队列移动
4. 确保 `DragOverlay` 正确工作

### 文件 2: `src/components/Scheduler/TaskCard.tsx`

1. 在 `useSortable` 的 `data` 中添加更多任务信息
2. 确保拖拽手柄正确绑定

### 文件 3: `src/components/Scheduler/QueueColumn.tsx`

1. 确保 `useDroppable` 的 id 和 data 正确设置
2. 确保 `SortableContext` 正确包裹任务列表

## 预期结果

- 拖拽过程中显示视觉反馈（目标队列高亮）
- 释放后任务移动到目标队列
- 后端 API 正确更新任务的 queue_level
