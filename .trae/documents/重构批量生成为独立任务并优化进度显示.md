我将按照您的建议进行重构，将“批量生成”优化为“独立任务并行生成”模式，并实现分题型的细粒度进度展示。

### 重构方案

1.  **后端架构升级**：
    *   **任务拆分**：修改后端 `BatchGenerateCards` 接口。不再创建一个巨大的 `batch_generate_questions` 任务，而是根据选中的节点数量，批量创建 N 个独立的 `generate_questions` 任务。这样每个节点互不干扰，且能天然利用系统的并行处理能力。
    *   **分步生成与进度汇报**：改造 `TaskProcessor` 中处理 `generate_questions` 的逻辑。
        *   不再一次性请求所有题目。
        *   **按题型拆分**：例如需求是 10 道题（含单选、多选），后端会自动将其拆分为“5道单选”和“5道多选”两次 AI 请求。
        *   **实时进度**：每完成一种题型的生成，立即更新该任务的进度条（例如：完成单选后进度更新为 50%）。
        *   **状态反馈**：任务中心将显示“正在生成单选题...”等具体状态。

2.  **前端交互优化**：
    *   **提交反馈**：批量生成弹窗提交后，提示“已创建 N 个生成任务”。
    *   **任务列表**：任务中心将列出所有独立的生成任务，用户可以清晰地看到每个知识点的生成情况（成功/失败/卡片数量）。
    *   **进度条适配**：复用并优化之前添加的进度条组件，使其支持单任务的详细进度展示。

### 预期效果

*   **并行高效**：多个知识点的题目生成将并行进行，大幅提升整体速度。
*   **进度透明**：您将看到每个任务从“准备中” -> “生成单选题” -> “生成多选题” -> “完成”的完整过程。
*   **容错性强**：某个节点的生成失败不会影响其他节点，且更容易定位问题（不会出现“共生成 0 张”这种模糊的整体失败）。

### 执行计划

1.  **修改后端 API (`ai.ts`)**：将批量生成接口改为批量插入 `generate_questions` 任务。
2.  **增强任务处理器 (`TaskProcessor.ts`)**：实现 `generate_questions` 的分题型循环调用与进度更新逻辑。
3.  **优化 AI 服务 (`aiService.ts`)**：确保 `generateCards` 支持更精准的题型控制。
4.  **前端适配**：微调任务中心的展示逻辑，确保新机制下的进度条显示正常。
