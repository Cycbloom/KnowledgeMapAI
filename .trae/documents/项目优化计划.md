# KnowledgeMap 项目优化计划

## 项目概述

KnowledgeMap 是一个基于知识图谱的学习应用，包含以下技术栈：
- **前端**: React 18 + TypeScript + Vite + TailwindCSS + Zustand
- **后端**: Express.js + TypeScript
- **数据库**: Supabase (PostgreSQL + pgvector)
- **缓存**: Redis (备用 NodeCache)
- **AI集成**: DeepSeek, 阿里云, 火山引擎

---

## 一、TypeScript 配置优化

### 问题分析
当前 `tsconfig.json` 配置过于宽松：
```json
{
  "strict": false,
  "noUnusedLocals": false,
  "noUnusedParameters": false,
  "noFallthroughCasesInSwitch": false,
  "forceConsistentCasingInFileNames": false
}
```

### 优化建议
1. **启用严格模式** - 分阶段启用 `strict: true`
2. **启用未使用变量检查** - `noUnusedLocals: true`, `noUnusedParameters: true`
3. **启用大小写一致性** - `forceConsistentCasingInFileNames: true`
4. **添加更多类型检查** - `noImplicitReturns`, `noUncheckedIndexedAccess`

### 预期收益
- 减少运行时错误
- 提高代码可维护性
- 更好的 IDE 支持

## 二、ESLint 配置优化

### 问题分析
当前 ESLint 配置非常基础，缺少：
- 未使用变量检测
- 代码复杂度检查
- 导入排序
- React 最佳实践规则

### 优化建议
1. **添加未使用变量规则**
2. **添加代码复杂度检查** (`complexity`, `max-lines-per-function`)
3. **添加导入排序** (`import/sort`)
4. **添加 React Hooks 完整规则**
5. **添加可访问性规则** (`jsx-a11y`)

## 三、代码质量优化

### 3.1 API 客户端优化 (`src/services/api.ts`)

**问题**:
- 文件过长（800+ 行）
- 流式请求处理逻辑重复
- Token 刷新逻辑可提取

**优化建议**:
1. 拆分为多个模块文件
2. 创建统一的流式请求处理器
3. 提取 Token 刷新逻辑到独立模块

### 3.2 状态管理优化

**问题**:
- `useGraphEditorState` 组合了 9 个子状态
- 状态分散在多个文件中

**优化建议**:
1. 考虑使用 React Context 分层管理
2. 添加状态持久化策略
3. 优化重渲染性能

### 3.3 后端服务优化

**问题**:
- `aiService.ts` 文件过长（900+ 行）
- `graphService.ts` 包含复杂的图算法

**优化建议**:
1. 拆分 AI 服务为多个专门服务
2. 提取图算法到独立工具类
3. 添加服务层单元测试

## 四、性能优化

### 4.1 前端性能

**问题**:
- Vite 配置的 chunk 分割不够精细
- 缺少组件懒加载优化
- PWA 缓存策略可优化

**优化建议**:
1. **优化 Chunk 分割**:
   ```js
   manualChunks: {
     'vendor-react': ['react', 'react-dom', 'react-router-dom'],
     'vendor-three': ['three', '@react-three/fiber', '@react-three/drei'],
     'vendor-markdown': ['react-markdown', 'remark-gfm', 'rehype-katex'],
     'vendor-charts': ['recharts', 'd3-force', 'd3-hierarchy'],
   }
   ```

2. **添加预加载策略**
3. **优化图片和字体加载**

### 4.2 后端性能

**问题**:
- 数据库查询缺少分页优化
- 缓存键设计可改进
- 批量操作可优化

**优化建议**:
1. **优化数据库查询**:
   - 添加查询超时
   - 使用数据库连接池
   - 优化 N+1 查询

2. **改进缓存策略**:
   - 添加缓存预热
   - 实现缓存雪崩保护
   - 添加缓存命中率监控

## 五、安全优化

### 5.1 认证安全

**问题**:
- Token 存储在 localStorage
- 缺少 CSRF 保护
- 缺少请求签名

**优化建议**:
1. 考虑使用 HttpOnly Cookie 存储 Token
2. 添加 CSRF Token
3. 实现请求签名验证

### 5.2 输入验证

**问题**:
- 部分接口缺少输入验证
- Zod Schema 未完全覆盖

**优化建议**:
1. 为所有 API 添加 Zod Schema 验证
2. 添加请求大小限制
3. 添加 SQL 注入防护

---

## 六、数据库优化

### 问题分析
- 向量索引使用 HNSW，可考虑 IVFFlat
- 缺少复合索引优化
- 缺少查询性能监控

### 优化建议
1. **添加复合索引**:
   ```sql
   CREATE INDEX idx_nodes_graph_level ON nodes(graph_id, level);
   CREATE INDEX idx_cards_user_next_review ON study_cards(user_id, next_review) WHERE next_review <= CURRENT_DATE;
   ```

2. **优化向量搜索**:
   - 考虑使用 IVFFlat 索引
   - 添加向量维度配置

3. **添加查询监控**:
   - 启用 pg_stat_statements
   - 添加慢查询日志
