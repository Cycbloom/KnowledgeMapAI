# KnowledgeMap 项目优化分析计划

## 项目概述

KnowledgeMap 是一个知识图谱管理应用，采用现代化技术栈：
- **前端**: React 18 + TypeScript + Zustand + React Query + Tailwind CSS
- **后端**: Express + Supabase + Redis + BullMQ
- **AI**: 支持多提供商（阿里云、DeepSeek、火山引擎）

---

## 一、TypeScript 配置优化

### 问题分析

当前 [tsconfig.json](file:///d:/KnowledgeMap/tsconfig.json) 配置过于宽松：

| 配置项 | 当前值 | 风险 |
|--------|--------|------|
| `strict` | `false` | 禁用所有严格类型检查 |
| `noImplicitAny` | `false` | 允许隐式 any 类型 |
| `strictNullChecks` | `false` | 禁用空值检查 |
| `noUnusedLocals` | `false` | 不检查未使用变量 |

### 优化方案

**阶段一：修复核心类型问题**
1. 修复 [src/types/index.ts](file:///d:/KnowledgeMap/src/types/index.ts) 中的 `any` 类型定义
2. 替换 `catch (error: any)` 为 `catch (error: unknown)`
3. 为高频 `any` 文件添加类型定义

**阶段二：逐步启用严格模式**
```json
{
  "strict": true,
  "noImplicitAny": true,
  "strictNullChecks": true,
  "noUnusedLocals": true,
  "noUnusedParameters": true
}
```

### 预期收益
- 减少运行时类型错误
- 提高 IDE 智能提示
- 增强代码可维护性

## 二、安全性优化

### 高优先级问题

| 问题 | 位置 | 风险等级 | 解决方案 |
|------|------|----------|----------|
| Token 存储在 localStorage | [useStore.ts:48-54](file:///d:/KnowledgeMap/src/store/useStore.ts#L48-54) | 高 | 迁移到 HttpOnly Cookie |
| Mermaid XSS 漏洞 | [Mermaid.tsx:8](file:///d:/KnowledgeMap/src/components/Mermaid.tsx#L8) | 高 | 改为 `securityLevel: 'strict'` |
| Logout 缺少身份验证 | [auth.ts:129-138](file:///d:/KnowledgeMap/api/routes/auth.ts#L129-138) | 高 | 添加 requireAuth 中间件 |
| 密码强度要求过低 | [schemas/index.ts:6](file:///d:/KnowledgeMap/api/schemas/index.ts#L6) | 中 | 提升最小长度到 8 位并要求复杂度 |

### 具体实施

**1. Token 存储优化**
```typescript
// api/routes/auth.ts - login 端点
res.cookie('access_token', session.access_token, {
  httpOnly: true,
  secure: process.env.NODE_ENV === 'production',
  sameSite: 'strict',
  maxAge: 60 * 60 * 1000,
});
```

**2. Mermaid 安全配置**
```typescript
// src/components/Mermaid.tsx
mermaid.initialize({
  securityLevel: 'strict', // 改为 strict
  // ...
});

// 添加 DOMPurify 净化
import DOMPurify from 'dompurify';
const sanitizedSvg = DOMPurify.sanitize(svg, {
  USE_PROFILES: { svg: true, svgFilters: true },
});
```

**3. 密码策略增强**
```typescript
// api/schemas/index.ts
password: z.string()
  .min(8, '密码至少需要8位')
  .regex(/[A-Z]/, '密码需要包含大写字母')
  .regex(/[a-z]/, '密码需要包含小写字母')
  .regex(/[0-9]/, '密码需要包含数字')
```

### React Query 优化

**问题**: invalidateQueries 范围过大
```typescript
// 当前实现 - useQueries.ts:381-385
onSuccess: () => {
  queryClient.invalidateQueries({ queryKey: ['graphData'] }); // 使所有图谱数据失效
}
```

**优化方案**: 使用精确的 queryKey
```typescript
onSuccess: (_, variables) => {
  queryClient.invalidateQueries({ queryKey: ['graph', variables.graphId] });
  queryClient.invalidateQueries({ queryKey: ['graphNodes', variables.graphId] });
}
```

### useEffect 依赖优化

**问题**: 使用 eslint-disable 忽略依赖警告
```typescript
// LearningMode.tsx:162-243
useEffect(() => {
  // ... 加载节点数据的逻辑
}, [nodeId]); // eslint-disable-next-line react-hooks/exhaustive-deps
```

**优化方案**: 正确声明所有依赖项，或使用 useCallback 包装内部函数

## 五、错误处理优化

### 统一错误处理机制

**问题**: 存在两套错误处理机制
- [errorService.ts](file:///d:/KnowledgeMap/src/services/errorService.ts)
- [useErrorHandler.ts](file:///d:/KnowledgeMap/src/hooks/useErrorHandler.ts)

**优化方案**: 创建统一的 `useApiOperation` hook
```typescript
export function useApiOperation() {
  const { addMessage } = useMessageStore();
  
  return useCallback(async <T>(
    operation: () => Promise<T>,
    options: {
      successMessage?: string;
      errorMessage?: string;
    }
  ) => {
    return createAsyncHandler(addMessage)(operation, options);
  }, [addMessage]);
}
```

### 错误边界增强

**问题**: 仅在根组件使用 ErrorBoundary

**优化方案**: 为关键组件添加独立错误边界
```typescript
<ErrorBoundary fallback={<GraphEditorFallback />}>
  <GraphEditor />
</ErrorBoundary>
```

## 十、总结

KnowledgeMap 项目整体架构合理，采用了现代化的技术栈和最佳实践。主要优化方向：

1. **安全性**: 修复 XSS 漏洞和 Token 存储问题
2. **类型安全**: 启用 TypeScript 严格模式
3. **性能**: 拆分大型组件，优化 React Query 使用
4. **代码质量**: 减少重复代码，统一错误处理

建议按照优先级逐步实施，确保每个阶段的改动都经过充分测试。
