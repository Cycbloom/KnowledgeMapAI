# Knowledge Map 业务逻辑全面分析

## Why

项目经过长期迭代，功能日益丰富，但缺乏系统性的业务逻辑梳理。通过全面分析，识别核心任务、梳理业务流程、发现优化机会，为后续迭代提供清晰的方向和依据。

## What Changes

- 识别并列出项目最重要的核心任务
- 系统梳理主要功能模块及其职责
- 分析关键数据流程和用户交互路径
- 总结关键业务规则
- 提出具体的优化建议和实施方向

## Impact

- Affected specs: 整体项目架构和业务逻辑
- Affected code: 全部代码目录

## 二、主要功能模块分析

### 2.1 知识图谱系统

**核心职责**：知识的可视化组织与关联管理

**关键组件**：

- `knowledge_graphs` - 图谱容器
- `knowledge_points` - 独立知识点实体（支持跨图谱复用）
- `graph_nodes` - 图谱-知识点关联（存储位置、层级等图谱特定属性）
- `edges` - 知识点之间的关系

**数据流向**：

```
用户创建图谱 → 添加知识点 → 建立关系 → AI 扩展 → 生成学习材料 → 创建闪卡
```

**业务规则**：

1. 知识点独立于图谱存在，支持跨图谱复用
2. 知识点有可见性控制：private/public/pending
3. 图谱支持软删除（deleted_at 字段）
4. 节点层级：root/core/sub/normal/leaf
5. 关系类型可自定义，支持多种线型和颜色

### 2.2 AI 智能辅助系统

**核心职责**：提供 AI 驱动的知识扩展、材料生成、问答能力

**关键组件**：

- `aiService` - AI 服务统一入口
- `ai/providers/` - 多提供商适配（Deepseek、火山引擎、阿里云）
- `taskProcessors/` - 异步任务处理器
- `prompt_templates` - 提示词模板管理

**数据流向**：

```
用户请求 → AI 服务 → 提供商适配 → API 调用 → 结果处理 → 数据存储
```

**业务规则**：

1. 支持多 AI 提供商，可配置切换
2. 提示词模板有优先级：graph > user > system
3. AI 操作有速率限制
4. 异步任务通过 BullMQ 队列处理
5. 向量嵌入用于语义搜索和相似度匹配

### 2.3 学习系统

**核心职责**：基于 FSRS 算法的间隔重复学习

**关键组件**：

- `study_cards` - 学习卡片（问答、选择、判断、填空、论述）
- `quiz_sets` - 测验集合
- `study_progress` - 学习进度追踪
- `studyService` - FSRS 算法实现

**数据流向**：

```
知识点 → 生成卡片 → 学习复习 → FSRS 评分 → 更新记忆状态 → 安排下次复习
```

**业务规则**：

1. 使用 FSRS（Free Spaced Repetition Scheduler）算法
2. 卡片类型：qa/choice/true_false/multi_choice/fill_in_the_blank/essay
3. 难度等级：1-5
4. 记忆状态字段：fsrs_state, fsrs_stability, fsrs_difficulty 等
5. 支持测验集合管理，可批量生成卡片

### 2.4 任务调度系统

**核心职责**：三层反馈队列任务管理与专注计时

**关键组件**：

- `scheduled_tasks` - 任务主表
- `queues` - 可配置的任务队列
- `task_executions` - 执行历史
- `task_dependencies` - 任务依赖关系
- `focus_sessions` - 专注会话记录

**数据流向**：

```
创建任务 → 分配队列 → 拖拽排序 → 开始专注 → 记录执行 → 完成任务
```

**业务规则**：

1. 三层队列架构：Q0（专注）、Q1（标准）、Q2（后台）
2. 任务类型：one_time/long_term/periodic/learning
3. 任务状态：pending/in_progress/paused/completed/cancelled
4. 支持任务依赖关系（strict/soft）
5. 番茄钟专注模式，支持休息提醒
6. 任务可关联知识点

### 2.5 学习路径系统

**核心职责**：结构化学习旅程规划与进度追踪

**关键组件**：

- `learning_paths` - 学习路径
- `learning_path_nodes` - 路径节点
- `learning_path_progress` - 用户进度
- `learning_plans` - 每日学习计划

**数据流向**：

```
创建路径 → AI 生成节点 → 设置目标 → 自动排程 → 学习执行 → 进度同步
```

**业务规则**：

1. 支持基于图谱结构或学习目标生成路径
2. 节点可设置里程碑标记
3. 支持前置知识依赖（prerequisites）
4. 可转换为任务调度器中的任务
5. 每日学习计划自动生成

### 2.6 成就激励系统

**核心职责**：游戏化激励与用户成长体系

**关键组件**：

- `achievements` - 成就定义
- `user_achievements` - 用户成就
- `periodic_tasks` - 周期性任务
- `periodic_passes` - 周期通行证
- `user_focus_stats` - 专注统计

**数据流向**：

```
用户行为 → 触发条件 → 解锁成就 → 获得经验值 → 等级提升
```

**业务规则**：

1. 成就类型：学习、专注、创作、任务完成等
2. 周期任务：weekly/monthly/quarterly
3. 通行证等级奖励系统
4. 连续学习天数追踪（streak）
5. 经验值与等级系统

## 三、数据流程分析

### 3.1 核心数据实体关系

```
users
  ├── knowledge_graphs (1:N)
  │     ├── graph_nodes (1:N) ──→ knowledge_points
  │     └── edges (1:N)
  ├── study_cards (1:N) ──→ knowledge_points
  ├── quiz_sets (1:N)
  ├── learning_paths (1:N)
  │     ├── learning_path_nodes (1:N)
  │     └── learning_plans (1:N)
  ├── scheduled_tasks (1:N)
  │     ├── task_subtasks (1:N)
  │     ├── task_links (1:N)
  │     └── task_knowledge_points (1:N)
  ├── focus_sessions (1:N)
  ├── user_achievements (1:N)
  └── periodic_tasks (1:N)
```

### 3.2 关键数据流

#### 知识创建流程

```
用户输入 → 创建 knowledge_point → 创建 graph_node → 建立关系 edge
         → AI 生成学习材料 → 更新 knowledge_point.content
         → AI 生成闪卡 → 创建 study_cards
         → 生成向量嵌入 → 更新 embedding
```

#### 学习复习流程

```
获取待复习卡片 → 展示卡片 → 用户评分(1-4) → FSRS 算法计算
              → 更新记忆参数 → 计算下次复习时间 → 更新 study_card
              → 更新 study_progress → 检查成就触发
```

#### 任务执行流程

```
选择任务 → 开始专注 → 创建 focus_session → 计时
        → 完成或中断 → 更新 task_execution → 更新 scheduled_task
        → 更新 user_focus_stats → 检查成就触发
```

## 五、关键业务规则总结

### 5.1 数据隔离规则

- 所有用户数据通过 `user_id` 隔离
- RLS（行级安全）策略确保数据访问安全
- 知识点支持 public 可见性，实现知识共享

### 5.2 AI 调用规则

- 所有 AI 操作有速率限制
- 支持多提供商配置和切换
- 异步任务通过队列处理，避免阻塞

### 5.3 学习算法规则

- FSRS 算法决定复习间隔
- 评分范围 1-4，影响记忆曲线
- 卡片状态：New → Learning → Review → Relearning

### 5.4 任务调度规则

- 三层队列优先级：Q0 > Q1 > Q2
- 任务依赖关系影响执行顺序
- 专注会话自动记录并更新统计

### 5.5 成就触发规则

- 基于用户行为自动触发
- 支持进度追踪（如连续学习天数）
- 周期性任务有独立的奖励系统

## 六、优化建议

### 6.1 架构优化

#### 短期优化（低风险）

1. **统一命名规范**
   - 服务文件统一命名：`xxxService.ts`
   - 路由文件统一命名：`xxxRoutes.ts` 或 `xxx.ts`
   - 类型定义统一位置

2. **整理配置文件**
   - 集中管理环境变量
   - 统一配置加载方式

3. **补充文档说明**
   - 为核心服务添加 JSDoc 注释
   - 更新 API 文档

#### 中期优化（中等风险）

1. **重组服务层目录结构**

   ```
   api/services/
   ├── core/           # 核心服务
   ├── ai/             # AI 相关
   ├── learning/       # 学习相关
   ├── scheduler/      # 调度相关
   └── common/         # 通用服务
   ```

2. **统一类型定义位置**
   - `shared/types/` 存放前后端共享类型
   - `src/types/` 存放前端专用类型
   - `api/types/` 存放后端专用类型

3. **完善错误处理**
   - 统一错误码定义
   - 完善错误日志记录

#### 长期优化（高风险）

1. **重构组件组织结构**
   - 按功能域划分子目录
   - 提取可复用组件

2. **统一状态管理方案**
   - 明确 Zustand store 划分规则
   - 减少组件内部状态

3. **完善测试覆盖**
   - 补充单元测试
   - 完善 E2E 测试

### 6.2 业务逻辑优化

#### 学习系统优化

1. **FSRS 参数可配置化**
   - 允许用户调整学习强度
   - 支持不同学习模式

2. **学习路径与任务调度深度整合**
   - 学习节点自动创建任务
   - 进度双向同步

3. **知识盲区检测**
   - 基于复习数据识别薄弱知识点
   - 自动生成针对性练习

#### 任务调度优化

1. **智能排程建议**
   - 基于历史数据推荐最佳执行时间
   - 考虑任务依赖关系自动排序

2. **专注模式增强**
   - 支持白噪音、环境音
   - 专注报告和洞察

#### AI 功能优化

1. **提示词模板管理增强**
   - 可视化编辑器
   - 版本管理

2. **AI 操作结果缓存**
   - 相似请求复用结果
   - 减少 API 调用

### 6.3 性能优化

1. **数据库查询优化**
   - 添加必要的复合索引
   - 优化 N+1 查询

2. **前端性能优化**
   - 组件懒加载
   - 虚拟列表优化大数据渲染

3. **缓存策略优化**
   - Redis 缓存热点数据
   - 合理设置缓存过期时间

### 6.4 用户体验优化

1. **新手引导优化**
   - 交互式引导流程
   - 功能发现提示

2. **移动端适配优化**
   - 响应式布局完善
   - 触摸交互优化

3. **无障碍支持**
