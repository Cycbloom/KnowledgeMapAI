# 修复题目类型筛选问题 - 产品需求文档

## 概述
- **Summary**: 修复闯关学习中题目生成时，即使只勾选一个类型，返回结果中仍然包含多种类型的问题。
- **Purpose**: 确保用户选择的题目类型得到严格执行，只生成用户指定类型的题目。
- **Target Users**: 使用闯关学习功能的用户。

## 问题分析
通过代码分析，发现问题出现在 `aiService.ts` 的 `generateCards` 函数中：
1. AI 生成卡片后，没有对返回的卡片进行类型过滤
2. 即使请求了特定类型的卡片，AI 可能返回其他类型，这些卡片也被直接保存到数据库中
3. 缺少最终的验证机制确保只返回和保存用户请求类型的题目

## 目标
- 确保只生成和保存用户指定类型的题目
- 在 AI 返回结果后进行严格的类型过滤
- 增强提示词，明确要求 AI 只生成指定类型的题目

## 非目标（范围外）
- 不修改用户界面
- 不修改数据库结构
- 不添加新的题目类型

## 背景与上下文
当前代码流程：
1. 用户在 GenerateCardsModal 中选择题目类型
2. 前端通过 API 提交请求，包含类型配置
3. generateQuestionsProcessor 按类型分别调用 generateCards
4. generateCards 调用 AI 生成题目，但没有过滤结果
5. 生成的题目直接保存到数据库

## 功能需求
- **FR-1**: 在 AI 生成卡片后，必须过滤掉非请求类型的卡片
- **FR-2**: 增强系统提示词，明确告知 AI 只生成指定类型的题目
- **FR-3**: 确保按类型单独生成时，也对结果进行验证

## 非功能需求
- **NFR-1**: 过滤逻辑必须高效，不显著影响生成速度
- **NFR-2**: 必须记录过滤后的卡片数量应尽可能接近请求数量

## 约束
- **技术**: 使用 TypeScript，遵循现有代码风格
- **业务**: 保持现有 API 接口不变
- **依赖**: 依赖现有 AI 服务和 Supabase

## 假设
- AI 有时会返回非请求类型的题目是正常现象
- 过滤掉不符合类型要求的题目是可接受的

## 验收标准

### AC-1: AI 生成后进行类型过滤
- **Given**: 用户请求生成特定类型的题目
- **When**: AI 返回题目结果
- **Then**: 只有与请求类型匹配的题目被保留
- **Verification**: `programmatic`

### AC-2: 增强提示词约束
- **Given**: 系统提示词包含明确的类型要求
- **When**: AI 生成题目
- **Then**: AI 更有可能只返回请求类型的题目
- **Verification**: `programmatic`

### AC-3: 数据库只保存正确类型
- **Given**: 题目生成完成
- **When**: 保存到数据库
- **Then**: 数据库中只包含用户请求类型的题目
- **Verification**: `programmatic`

### AC-4: 保持题目数量尽可能接近
- **Given**: 用户请求 N 道特定类型的题目
- **When**: 过滤后剩余题目数量少于 N
- **Then**: 系统应该记录警告，但不尝试重新生成
- **Verification**: `programmatic`
