# 知识图谱缩放文字显示优化 - 产品需求文档

## Overview
- **Summary**: 优化知识图谱在不同缩放级别下的文字显示效果，确保在缩放较小时文字不会过小，在缩放较大时按层级过滤低层级文字。
- **Purpose**: 解决当前图谱缩放时文字显示不合理的问题，提升用户体验。
- **Target Users**: 使用知识图谱功能的所有用户。

## Goals
- 优化缩放较小时的文字显示，确保文字清晰可读
- 实现按层级的文字过滤，在缩放较大时只显示高级别节点文字
- 保持缩放体验的流畅性

## Non-Goals (Out of Scope)
- 改变图谱的整体布局算法
- 修改节点的基本样式
- 增加新的交互功能

## Background & Context
- 当前实现中，文字大小是基于 `baseFontSize / zoomLevel` 计算的，导致缩放较小时文字过小
- 文字显示的阈值设置可能不合理，导致在某些缩放级别下文字显示效果不好
- 没有按层级进行有效的文字过滤，在缩放较大时所有级别的文字都显示，导致界面混乱

## Functional Requirements
- **FR-1**: 优化文字大小计算逻辑，确保在不同缩放级别下文字都清晰可读
- **FR-2**: 实现按层级的文字过滤，在缩放较大时只显示高级别节点文字
- **FR-3**: 保持缩放交互的流畅性

## Non-Functional Requirements
- **NFR-1**: 文字显示变化应该平滑过渡，避免突兀的显示/隐藏
- **NFR-2**: 优化后的文字显示不应该影响图谱的整体性能
- **NFR-3**: 保持与现有代码风格和架构的一致性

## Constraints
- **Technical**: 基于现有的 React 组件架构，不引入新的依赖
- **Performance**: 优化后的实现应该保持良好的性能，即使在节点数量较多的情况下

## Assumptions
- 节点层级分为：root、core、sub、normal、leaf
- 缩放级别范围为 0.1 到 5

## Acceptance Criteria

### AC-1: 缩放较小时文字清晰可读
- **Given**: 用户缩小组图谱到较小的缩放级别（如 0.1-0.3）
- **When**: 查看图谱中的节点文字
- **Then**: 文字应该保持清晰可读，不会因为缩放过小而变得模糊或无法辨认
- **Verification**: `human-judgment`

### AC-2: 缩放较大时按层级过滤文字
- **Given**: 用户放大图谱到较大的缩放级别（如 0.8-5）
- **When**: 查看图谱中的节点文字
- **Then**: 低层级节点（如 leaf 级）的文字应该被过滤，只显示高级别节点的文字
- **Verification**: `human-judgment`

### AC-3: 文字显示过渡平滑
- **Given**: 用户在不同缩放级别之间切换
- **When**: 观察文字的显示/隐藏变化
- **Then**: 文字的显示/隐藏应该平滑过渡，避免突兀的变化
- **Verification**: `human-judgment`

### AC-4: 性能保持良好
- **Given**: 图谱中包含大量节点（如 100+）
- **When**: 用户进行缩放操作
- **Then**: 缩放操作应该保持流畅，不会因为文字显示优化而出现卡顿
- **Verification**: `human-judgment`
