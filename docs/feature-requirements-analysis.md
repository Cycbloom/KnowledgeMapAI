## 一、项目背景与定位

### 1.1 项目性质

KnowledgeMap 是一个**个人使用**的知识库搭建项目，用于学习与研究。本次需求分析在已完成的 v1.0.0 基础上拓展新功能，参考市面上竞品的优秀功能进行学习借鉴。

### 1.2 核心定位

**学习中心 = 学习工作流编排**

不是单一仪表盘，也不是数据分析中心，而是把学习行为串成可执行的工作流：

```
输入 → 整理 → 理解 → 记忆 → 检验
```

每个环节都有对应功能支撑，环节之间无缝衔接。

### 1.3 使用场景

| 场景 | 说明 |
|------|------|
| 学科/系统学习 | 编程、数学、语言等系统性学科，循序渐进、长期积累 |
| 研究/深度思考 | 论文阅读、文献综述、思想沉淀，强调关联与涌现 |
| 兴趣/泛读吸收 | 读书笔记、文章收藏、播客/视频知识提取 |
| 个人管理 | 番茄钟、工作活动进度、工作记录留痕、资料归档 |

> 注：个人管理是用户主动扩展的方向，将知识库从"纯学习"拓展为"学习 + 工作生活管理"双中心。

### 1.4 对标竞品

| 竞品 | 借鉴方向 |
|------|---------|
| Obsidian / Logseq | 双向链接、块级引用、Daily Notes、本地优先 |
| Notion / Heptabase | 数据库视图、白板/Canvas、结构化组织 |
| Anki / RemNote | FSRS 间隔重复、笔记即卡片、上下文卡片 |
| Readwise Reader / Cubox | 稍后读、高亮批注、自动归集、订阅流 |

## 二、功能域划分与减法决策

经过多轮对话收敛，将所有可能借鉴的功能划分为 7 个功能域，并进行了域级减法。

### 2.1 功能域全景

| 域 | 名称 | 竞品强项 | 决策 |
|----|------|---------|------|
| A | 知识输入与捕获 | Readwise/Cubox | **保留** |
| B | 知识组织与关联 | Obsidian/Logseq/Heptabase | **保留** |
| C | 知识理解与深化 | AI + Heptabase | 暂缓 |
| D | 知识记忆与巩固 | Anki/RemNote | **保留** |
| E | 知识检验与产出 | Notion/Heptabase | 暂缓 |
| F | 个人管理与记录 | 用户扩展方向 | **保留** |
| G | 跨环节基础能力 | - | 部分保留 |

### 2.2 用户偏好画像

减法决策反映出清晰的用户偏好：

- **重输入轻产出**：保留 A 域（输入），暂缓 E 域（检验产出）
- **重组织轻深化**：保留 B 域（组织关联），暂缓 C 域（AI 深化理解）
- **重记忆轻检验**：保留 D 域（记忆巩固），暂缓 E 域（组卷模考）
- **重记录轻管理**：保留 F 域的记录类功能（留痕、习惯、统计），暂缓管理类功能（GTD、项目进度）

### 2.3 明确不做的功能

| 功能 | 不做原因 |
|------|---------|
| C2 费曼学习法引导 | 现有 AI 对话够用 |
| C4 相似概念辨析 | 现有 AI 扩展够用 |
| C7 苏格拉底式问答 | 现有 AI 够用 |
| C8 知识盲区检测 | 由 D5 薄弱点诊断覆盖部分需求 |
| E1 组卷/模拟考试 | 暂不需要应试检验 |
| E2 学习报告自动生成 | 由 F3 日报/周报覆盖 |
| E5 输出驱动学习 | 暂不需要 |
| E6 项目式学习追踪 | 暂不需要 |
| F2 项目进度可视化 | 暂不需要 |
| F8 GTD 收件箱处理 | 现有三层队列够用 |
| G8 命令面板 | 现有快捷键体系够用 |

## 三、保留域功能清单

### 3.1 A 域 · 知识输入与捕获

| 编号 | 功能 | 性质 | 说明 |
|------|------|------|------|
| A1 | 统一收件箱 | 新建 | 网页/PDF/RSS/Newsletter 聚合到一处，待处理后转为节点 |
| A2 | 浏览器剪藏插件 | 新建 | 独立 Chrome/Edge 扩展，支持全文/选中/截图/PDF 多模式剪藏 |
| A3 | PDF/网页高亮批注 | 新建 | 内置阅读器，高亮自动转为知识卡片素材 |
| A4 | 视频字幕提取+时间戳笔记 | 新建 | B 站/YouTube 字幕抓取，笔记带时间戳跳转 |
| A5 | 播客订阅+转写 | 增强 | 已有 STT 能力，补订阅源管理和转写文本关联节点 |
| A8 | Newsletter/RSS 订阅 | 新建 | 邮箱绑定 + RSS 源管理，自动入库收件箱 |

**关键决策**：
- A2 采用**独立浏览器扩展**形式（非应用内浏览器窗口），接受工作量极大但体验最佳
- A1 收件箱是 A 域基础，A2-A8 都依赖 A1

### 3.2 B 域 · 知识组织与关联

| 编号 | 功能 | 性质 | 说明 |
|------|------|------|------|
| B1 | 双向链接 / 反向链接 | 新建 | 节点间 `[[]]` 引用，反向链接面板显示来源 |
| B2 | 块级引用 | **暂缓** | 节点内段落/卡片可独立被引用（需要重构内容模型） |
| B3 | 双链与图谱边同步 | 整合 | 双链自动生成图谱边，图谱边可反向生成双链 |
| B6 | Daily Notes / 日记 | 新建 | 每日一篇，时间戳条目，可在日记中 `[[]]` 引用节点 |

**关键决策**：
- **B2 块级引用暂缓**，避免重构 `knowledge_points.content` 内容模型
- B1 采用**节点级双链**（图谱节点之间 `[[]]` 引用），与现有图谱契合度高
- 双链语法复用现有 `markdownParser` 已有的 `[[]]` 解析能力，但需升级为运行时实时解析

### 3.3 D 域 · 知识记忆与巩固

| 编号 | 功能 | 性质 | 说明 |
|------|------|------|------|
| D2 | 笔记即卡片（节点级） | 增强 | 节点内容直接生成卡片，卡片与源节点双向关联 |
| D4 | 错题本 | 新建 | 复习失败的卡片自动进入错题本，独立强化模式 |
| D5 | 薄弱点诊断+强化 | 新建 | 基于复习数据识别薄弱节点，推荐针对性卡片 |
| D7 | 上下文卡片 | 增强 | 卡片正面显示原文出处，点击跳转源节点 |
| D8 | 跨图谱混合复习 | 新建 | 全局复习队列，按遗忘曲线+科目权重智能混合 |

**关键决策**：
- **D2 降级为节点级卡片**（不做段落级），因为 B2 块级引用暂缓
- D2 是 D 域基础，D7 依赖 D2
- D5 依赖 D4
- D5 可复用现有 `dashboard.blindSpots`（低稳定度卡片 Top10）作为起点

### 3.4 F 域 · 个人管理与记录

| 编号 | 功能 | 性质 | 说明 |
|------|------|------|------|
| F3 | 日报/周报自动生成 | 新建 | 基于当日任务+学习+活动数据自动汇总，可编辑补充 |
| F4 | 项目空间+资料归档 | 新建 | **复用 graph 作为项目载体**，通过标签/属性区分"学习图谱"与"项目空间" |
| F6 | 习惯追踪看板 | 新建 | 习惯定义+打卡+连续天数+完成率可视化 |
| F7 | 全维度时间统计 | 增强 | 按活动/项目/标签维度的时间投入统计与图表 |

**关键决策**：
- **F4 不新建 projects 表**，复用 graph 作为项目空间载体，零概念增量
- F3 复用现有 `WeeklyReport`/`MonthlyReport` 组件和 `task_reviews` 表，升级为跨维度综合报告
- F6 复用现有 `periodic_tasks` 表的 streak 机制

## 四、与现有功能的关系

### 4.1 现有基础可复用

| 现有能力 | 可复用于 |
|---------|---------|
| `edges` 表 + `relates_to` 关系类型 | B1 双向链接的底层承载 |
| `markdownParser` 的 `[[]]` 解析 | B1 运行时双链的语法基础 |
| `study_cards.knowledge_point_id` 关联 | D2 笔记即卡片、D7 上下文卡片 |
| `practice_results` / `quiz_results` 表 | D4 错题本的数据源 |
| `dashboard.blindSpots` API | D5 薄弱点诊断的起点 |
| `WeeklyReport` / `MonthlyReport` 组件 | F3 综合报告的组件基础 |
| `task_reviews` 表（review_type='daily'） | F3 日报的反思记录载体 |
| `periodic_tasks` 表 + streak 字段 | F6 习惯追踪的底层机制 |
| 各类统计 API（`/statistics`、`/dashboard`、`/scheduler/analytics`） | F7 全维度时间统计的数据源 |
| STT 能力（qwen3-asr-flash） | A5 播客转写 |
| OCR 图片识别 | A 域多模态输入 |

### 4.2 完全新建的部分

| 功能 | 说明 |
|------|------|
| B6 Daily Notes | 无任何现有基础，需新建 `daily_notes` 表 + 日记页面 |
| A1 统一收件箱 | 无任何现有基础，需新建收件箱表 + 处理流程 |
| A2 浏览器扩展 | 独立项目，需新建 Chrome/Edge 扩展 + 通信机制 |
| D8 跨图谱混合复习 | 现有复习是单图谱维度，需新建全局队列与混合策略 |
| F6 习惯追踪看板 | 无 `habits` 表，需新建习惯模型 + 打卡机制 |

### 4.3 现状对照关键发现

| 发现点 | 影响 |
|--------|------|
| `knowledge_points.content` 是单一 TEXT 字符串，不支持块级内容 | B2 块级引用若做需重构内容模型（已决定暂缓） |
| `graph_nodes` 不存储内容，只是图谱定位表 | 双链的对象是 knowledge_point，不是 graph_node |
| `edges` 表是单向有向边 | 双链可通过 `relates_to` 类型双向记录或单向+反向查询实现 |
| `study_cards` 无 `node_id` 字段，通过 `knowledge_point_id` 间接关联 | D7 上下文卡片需通过 `knowledge_point_id` → `graph_nodes` 跳转 |
| `task_type` 取值无 `work`/`habit` | F 域若需区分工作/习惯任务，需扩展 task_type 枚举 |
| 无 `projects` 表 | F4 已决定复用 graph，不新建项目概念 |

## 五、关键决策记录

| 决策编号 | 决策内容 | 决策理由 |
|---------|---------|---------|
| D-001 | B2 块级引用暂缓 | 重构内容模型工作量极大，性价比不高 |
| D-002 | D2 降级为节点级卡片 | 受 D-001 影响，无法做段落级关联 |
| D-003 | A2 采用独立浏览器扩展 | 体验最佳，接受工作量极大 |
| D-004 | F4 复用 graph 作为项目空间 | 零概念增量，避免新建 projects 表 |
| D-005 | 路线图顺序：B→D→F→A | 基础设施优先，避免返工 |
| D-006 | Phase 1 包含 B1+B6+D2+D7 | 一次性完成"组织+卡片"基础 |
| D-007 | 文档拆分为三份 | 需求分析 + 竞品对标 + 路线图，职责清晰 |
| D-008 | 路线图粒度为功能级 | 不拆任务，不给时间估算 |

## 六、非功能性约束

继承自项目规则（`.trae/rules/project_rules.md`）：

| 约束 | 说明 |
|------|------|
| 类型安全 | 禁止 `any` 类型、禁止非空断言 `!`、使用可选链和空值合并 |
| 前端日志 | 禁止 `console.log/info`，允许 `warn/error` |
| 后端日志 | 使用 `logger` 工具，禁止 `console.*` |
| API 命名 | 遵循 `api-naming-conventions.md`（如 `graphsApi.list()` 而非 `graphsApi.getGraphs()`） |
| 目录边界 | `api/` 和 `src/` 只能依赖 `shared/`，不能互相依赖 |
| 数据库修改 | 直接修改 `supabase/migrations/` 模块化文件，schema 变更后运行 `npm run db:gen-types` |
| AI 服务规范 | Prompt 必须从数据库读取，必须记录性能数据 |
| 缓存机制 | 优先使用 `getOrSet`，使用标签便于批量失效 |
